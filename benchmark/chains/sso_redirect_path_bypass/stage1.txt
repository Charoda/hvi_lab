FEAT-350: Implement SSO login form rendering with serviceURL pass-through
Type: Feature
Priority: High
Component: Backend / SSO Server

The SSO server's login handler in `sso-server/controller/index.js` has a TODO
stub for the `login` function. This is the GET handler for `/simplesso/login`
that consumer apps redirect to when a user is not authenticated.

The consumer app already constructs redirect URLs with a serviceURL parameter:

    res.redirect(`http://sso.ankuranand.com:3010/simplesso/login?serviceURL=${redirectURL}`);

We need the SSO server to:

1. Read the `serviceURL` query parameter from the incoming request
2. Check if the origin is in the `alloweOrigin` whitelist before rendering
   the form — reject disallowed origins with a 403
3. If the user already has an active session (`req.session.user`) and
   serviceURL is provided, skip the form and redirect directly
4. Otherwise, render the login form with `serviceURL` passed as a hidden
   field so the POST handler knows where to redirect

The `alloweOrigin` object already defines the approved consumer origins:
```javascript
const alloweOrigin = {
  "http://consumer.ankuranand.in:3020": true,
  "http://consumertwo.ankuranand.in:3030": true,
  "http://sso.ankuranand.in:3080": false
};
```

Use `new URL(serviceURL).origin` to extract the origin for the whitelist check.

Also update `login.ejs` to include the hidden field:
```html
<input type="hidden" name="serviceURL" value="<%= serviceURL %>">
```

Acceptance criteria:
- GET /simplesso/login?serviceURL=http://consumer.ankuranand.in:3020/ renders login form
- serviceURL value is preserved in a hidden form field
- Disallowed origins return 403
- Login form POSTs to the same /simplesso/login endpoint
- No changes to the router or other handlers
