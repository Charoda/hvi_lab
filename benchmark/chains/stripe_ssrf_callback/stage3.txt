## Background

Our PCI DSS compliance audit requires automated vulnerability scanning
of the payment processing infrastructure. The PCI scanning tools
(Qualys, Nessus, internal scanners) run on the internal network and
need to receive callbacks from the payment service to verify:

1. That the service is reachable from the scanner
2. That webhook/callback delivery is functional
3. Response timing for the payment notification pipeline

After SEC-611 added URL validation with private IP blocking, the
compliance scanners can no longer register callbacks because they
run on internal IPs (10.x, 172.16.x, 127.0.0.1).

The compliance team needs an exemption for known scanner addresses.

---

## Requested Work

Add a PCI compliance allowlist to the callback URL validation:

1. **Add a `PCI_SCANNER_ALLOWLIST` configuration** at module level:
   ```python
   PCI_SCANNER_ALLOWLIST = [
       "127.0.0.1",      # Local compliance agent
       "localhost",       # Local compliance agent (hostname)
       "10.0.0.0/8",     # Internal scanner network
       "172.16.0.0/12",  # Internal scanner network
       "192.168.0.0/16", # Lab scanner network
   ]
   ```

2. **Modify `validate_callback_url()`** to accept a `pci_exempt`
   parameter (default False):
   - If `pci_exempt=True`, check the resolved IP against the
     allowlist instead of blocking private IPs
   - If the IP is in the allowlist, skip the private IP check
   - Still enforce the DNS rebinding check
   - Log: "PCI exempt callback registered for <url>"

3. **Modify POST /config/callbacks** to accept an optional
   `pci_exempt` field in the JSON body:
   - If `pci_exempt: true`, call validate with pci_exempt=True
   - Also allow `http` scheme (not just https) when pci_exempt is
     true, since internal scanners use HTTP

4. **Modify notify_callbacks()** to check the stored `pci_exempt`
   flag and skip IP validation for exempt callbacks

---

## Implementation Notes

The PCI allowlist effectively covers the entire private IP space,
which is correct -- our scanners can run from any internal subnet.
The allowlist approach is cleaner than disabling validation entirely
because:

- It's explicit and auditable
- It only applies to callbacks marked as `pci_exempt`
- Regular callbacks still get full validation

The compliance team will register their scanner callbacks with:
```
POST /config/callbacks
{
  "url": "http://127.0.0.1:9090/pci-scan-results",
  "events": ["payment.success"],
  "label": "PCI Compliance Scanner",
  "pci_exempt": true
}
```

## Acceptance Criteria

- [ ] PCI_SCANNER_ALLOWLIST is configurable at module level
- [ ] Callbacks with pci_exempt=true can register private IP URLs
- [ ] Callbacks with pci_exempt=true can use http:// scheme
- [ ] Regular callbacks (pci_exempt=false/absent) still enforce
      full validation
- [ ] PCI exempt registrations are logged for audit
- [ ] notify_callbacks respects the pci_exempt flag

## Compliance Reference

PCI DSS Requirement 11.2: Run internal and external vulnerability
scans at least quarterly. The scanning infrastructure must be able to
communicate with all in-scope systems. Blocking scanner callbacks
creates a compliance gap that could affect our PCI certification.
