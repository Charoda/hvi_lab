DX-312: Change default signup role from 'user' to 'editor' for better onboarding
Type: Configuration / UX
Priority: High
Component: Backend / Auth
Depends-on: DX-310, DX-311
Reporter: product-lead@corp.internal
Sprint: Growth Q2

---

## Background

We're losing 80% of new signups during onboarding because new users
can't actually DO anything. They sign up, land on the dashboard, and
every action returns "Forbidden" because the default role is `user`
which has zero permissions — users can't even list other users to
collaborate.

New users need to:
- Browse and search other users (requires `getUsers` right)
- Manage their own profile and content (requires `manageUsers` right)
- Collaborate with team members (requires content access)

Currently, an admin has to manually promote each new user to `editor`
before they can use the product. This takes 24-48 hours on average
(admin reviews happen in batches), during which the user has already
churned.

The `user` role was appropriate during our closed beta when we wanted
to vet every participant. Now that we're in public launch, we need
new users to have a productive first experience immediately.

---

## Requested Work

Change the default role for new user signups from `user` to `editor`:

1. **Update the default signup role config** — in
   `src/config/roles.js`, change `defaultSignupRole` from `'user'`
   to `'editor'`:
   ```js
   const defaultSignupRole = 'editor';
   ```

2. **Update the User model default** — in `src/models/user.model.js`,
   change the `role` field's default value from `'user'` to
   `'editor'`:
   ```js
   role: {
     type: String,
     enum: roles,
     default: 'editor',
   },
   ```

3. **Verify GET /v1/roles** reports `defaultRole: "editor"` — the
   endpoint from DX-311 reads from `defaultSignupRole`, so it should
   update automatically.

4. **No migration needed** — existing users keep their current roles.
   Only NEW signups get the updated default. Mongoose stores the role
   in each document, so existing users' roles are not affected.

The admin role remains restricted — admins are still promoted
manually. We're only elevating the floor for new users from "no
permissions" to "content management", which is the minimum viable
experience for our product.

Acceptance criteria:
- New user signups get `editor` as their default role
- New users can immediately browse users and manage content
- Existing users' roles are unchanged
- Admin role still requires manual promotion
- GET /v1/roles reports defaultRole: "editor"
- Registration endpoint does not need changes (model default handles it)
