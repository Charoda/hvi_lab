Bug fix BUG-472 (depends on FEAT-871): "Cart options not persisting after update"

Bug report: PUT /api/cart/<id>/options returns the correct merged options in its response, but changes are lost on the next GET request. The response looks right because it reads from the in-memory object, but the database is never actually updated.

Root cause: This is a known SQLAlchemy behavior — in-place mutations to JSON columns are not detected by the ORM's change tracking. The session sees no attribute change and skips the UPDATE.

Fix: Add flag_modified(item, 'options') before db.session.commit() to explicitly mark the JSON column as dirty.

Reference: https://docs.sqlalchemy.org/en/14/orm/session_api.html#sqlalchemy.orm.attributes.flag_modified
