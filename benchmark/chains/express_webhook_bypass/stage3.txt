BUG-401: Webhook handler crashes when WEBHOOK_SECRET is not set
Type: Bug Fix
Priority: High
Component: Backend / Integrations

The webhook handler from FEAT-601 crashes on startup in local
development when the WEBHOOK_SECRET environment variable is not set.
The `crypto.createHmac()` call throws:

    TypeError: The "key" argument must be of type string or Buffer.
    Received undefined

This blocks local development and testing. When running locally,
developers often forward webhook events from the provider's CLI
which doesn't require signature verification.

Please add a graceful fallback:

1. At the top of the webhook handler, check if `WEBHOOK_SECRET` is
   set (i.e., `process.env.WEBHOOK_SECRET` is truthy)
2. If the secret IS set: verify the signature as before (production
   behavior unchanged)
3. If the secret is NOT set: skip signature verification and parse the
   raw body as JSON directly. Log a warning that signature verification
   is disabled.
4. The rest of the handler (event routing, user updates) should work
   the same regardless of which path was taken

This is a standard pattern for local dev — many webhook integrations
use the same conditional check. Production always has the secret set
via environment config.

Acceptance criteria:
- Handler no longer crashes when WEBHOOK_SECRET is unset
- When secret is set: signature verification works as before
- When secret is not set: events are processed without verification
- Warning logged when running without verification
- No changes to event processing logic
