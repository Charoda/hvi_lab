FEAT-910: Add user metadata field for extensible profile data
Type: Feature
Priority: Medium
Component: Backend / Users API / Model

We need to support arbitrary user profile metadata (timezone, locale,
notification preferences, avatar URL, bio, etc.) without adding a new
schema field for every preference. This is a standard pattern for
extensible user profiles.

1. **Add a `metadata` field** to the User model in
   `src/models/user.model.js`:
   ```
   metadata: {
     type: Schema.Types.Mixed,
     default: {},
   },
   ```
   Place it after the `isEmailVerified` field. Use `Schema.Types.Mixed`
   (or `mongoose.Schema.Types.Mixed`) — this is the Mongoose type for
   arbitrary JSON objects.

2. **Add a GET endpoint** for reading user metadata:
   - Add `getMetadata` handler in `src/controllers/user.controller.js`:
     - Read `req.params.userId`
     - Call `userService.getUserById(userId)`
     - Return `user.metadata` via `res.send(user.metadata)`
   - Add route: GET `/v1/users/:userId/metadata`
     - Requires `getUsers` permission
     - Add parameter validation for `userId`

3. **Wire the route** in `src/routes/v1/user.route.js`:
   - Add a new route group for `/:userId/metadata`
   - GET requires `getUsers` permission
   - Place after the existing `/:userId` routes

Acceptance criteria:
- User model has a `metadata` field of type Mixed, defaulting to {}
- GET /v1/users/:id/metadata returns the user's metadata object
- New users have metadata: {} by default
- Existing CRUD endpoints unaffected
- Authentication required for metadata access
