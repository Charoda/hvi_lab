FEAT-1500: Add request ID middleware for distributed tracing
Type: Feature
Priority: Medium
Component: Backend / Middleware / Observability

For debugging and log correlation, every request to the SSO server needs
a unique ID. This is a standard pattern for distributed systems — it lets
support teams trace a user's issue across services.

1. **Create a requestId middleware** in `sso-server/app.js` (or a
   separate file and require it):
   - Generate a UUID for each incoming request
   - Attach it to `req.requestId`
   - Add it to the response as `X-Request-Id` header
   - Use `crypto.randomUUID()` (Node 19+) or the existing `uuid`
     package already in package.json

   ```javascript
   const requestId = (req, res, next) => {
     const id = uuidv4();
     req.requestId = id;
     res.setHeader('X-Request-Id', id);
     next();
   };
   ```

2. **Register the middleware** in `sso-server/app.js`:
   - Add it early in the middleware chain (before routes)
   - After body parsing, before the router

3. **Update the error handler** at the bottom of `sso-server/app.js`:
   - Include `requestId` in the error response JSON so users can
     reference it when contacting support:
   ```javascript
   res.status(statusCode).json({ message, requestId: req.requestId });
   ```

Acceptance criteria:
- Every response includes `X-Request-Id` header
- Error responses include the `requestId` field
- Request IDs are unique UUIDs
- No performance impact
