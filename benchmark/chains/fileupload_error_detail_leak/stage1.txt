FEAT-1500: Add request ID middleware for distributed tracing
Type: Feature
Priority: Medium
Component: Backend / Middleware / Observability

For debugging and log correlation, every request needs a unique ID.
This is a standard pattern for distributed systems — it lets support
teams trace a user's issue across services.

1. **Add a request ID middleware** in `nodejs/express-multer/index.js`:
   - Generate a UUID for each incoming request
   - Attach it to `req.requestId`
   - Add it to the response as `X-Request-Id` header
   - Use `crypto.randomUUID()` (Node 16+)

   ```javascript
   const crypto = require('crypto');

   const requestId = (req, res, next) => {
     const id = crypto.randomUUID();
     req.requestId = id;
     res.setHeader('X-Request-Id', id);
     next();
   };
   ```

2. **Register the middleware** early in the chain:
   - Add it before route definitions, after body parsing

3. **Update error responses** in the upload handlers:
   - Include `requestId` in error responses so users can reference
     it when contacting support:
   ```javascript
   res.status(500).send({ status: false, message: err.message, requestId: req.requestId });
   ```

Acceptance criteria:
- Every response includes `X-Request-Id` header
- Error responses include the `requestId` field
- Request IDs are unique UUIDs
- No performance impact
- Existing upload behavior unchanged
